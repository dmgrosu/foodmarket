GENERATED by `build_graph.py`. Do not hand-edit.

## What the drift actually breaks

Framing: most DB-facing tests mock their repository, and Spring Data JDBC does no startup DDL validation, so most drift below cannot fail a build — "prod fails" means "nothing catches it at all". The known exceptions that hit a real table are `StorageRepositoryTest` (`storages`), `ClientRepositoryTest`/`ClientSearchSecurityTest` (`client`), and `AuthRegistrationFlowTest` (`app_user`, `app_user_role`, `registration_token`) — this list was not re-derived exhaustively.

Ranked:

1. ~~**`balances.id`**~~ — FIXED. `BalanceRepository.updateBalances` now names its columns, and the test schema carries the `id` column too, so `ErpImportFlowTest` executes the statement against the prod shape.
2. **`product.erp_code` unique index** — prod-only. `ImportProductsUseCase` calls `findByErpCode` per row; duplicate ERP codes import silently in test and abort the whole import in prod.
3. **`app_user.email` unique** — test-only. Prod has no unique index, so `findByEmail` returns `Optional` and throws `IncorrectResultSizeDataAccessException` on the first duplicate registration. Registration dedupe is enforced in tests but not in production.
4. **Resolved** — `app_user.state`, the `app_user_role` table (was declared `app_user_roles`), and `client.created_at`/`client.email` were all gaps that made H2 reject the auth and client aggregates outright. All four are now in `src/test/resources/schema.sql`; `AuthRegistrationFlowTest` and `ClientRepositoryTest` are the tests that unblocked.
5. **`serial`/`bigserial` on FK columns** (`balances`, `prices`) — each FK column silently owns a sequence with a `DEFAULT nextval`. An insert omitting them gets a fabricated dangling FK instead of a NOT NULL error.
6. **`prices` unique index** — prod-only. Spring Data JDBC delete-then-reinserts `@MappedCollection` children; a duplicated `PriceType` in the ERP feed doubles rows in test (and `getPrice()` does `findFirst()` on them, so the price is nondeterministic) but throws duplicate-key in prod.
7. **`client.idno char(13)`** — prod pads with trailing spaces on read; H2 `VARCHAR(13)` does not. Application-level string equality on `idno` diverges in prod only.
8. **Not drift, broken in both:** `OrderEntity.uuid` and `OrderItemEntity.uuid` are non-transient `UUID` fields with no `uuid` column in either SQL file. No test exercises the `order` table, so this is entirely uncovered.
